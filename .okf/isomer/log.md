# Directory Update Log

## 2026-09-23

- **Slides redesign**: The pack follows a Claude Design review. New theme (spec colors in light and dark, an inverse tone for title, section, and closing slides, type roles, nothing below 24px, `primary`/`pink` as the only hues), a footer-only frame, sixteen new primitives, and restyles of the rest. `slideCardGroup`, `slideFlow`, and `slideCycle` are retired; `slideTitle` loses `lede`, `size`, and `tone`; `slideFrame` trades `layout` and `footer` for `tone` and `url`; `slideSplit` columns and `slideCode` panels are reshaped. The pack gains an agent authoring guide and `resolveSlideRenders`. The Isomer deck is rebuilt on it as 24 slides in five sections.
- **Slides studio**: `apps/slides-studio` serves the slides runtime over MCP with deck tools and a live viewer, for an agent to write a deck while you watch.
- **JSX shim**: `toComposition` converts author elements nested anywhere inside a prop's plain objects and arrays.
- **Frame `url`**: `slideFrame.url` must be an absolute `http(s)` address; a relative one is rejected by validation and dropped at render.
- **Studio pages**: The slides studio has a landing page with the connection instructions and every deck, a live slide grid per deck at `/decks/<id>`, and the viewer at `/decks/<id>/present`. The viewer lists a slide's validation errors instead of failing on it.
- **Source panel**: The deck viewer's surface tabs are outputs only; a Source panel beside the stage shows a slide's JSX and JSON (`?source=jsx|json`, `s` to toggle), and old `surface=jsx` links open it. The shim's new `toJsx` prints a composition back to JSX that `toComposition` parses to the same value, so the studio shows agent-written slides as JSX too; round-trip tests cover every pack example and every Isomer deck slide.
- **Slide size steps**: Length-sensitive slide primitives (heading, stats, timeline, pipeline, columns, definitions, graph, and the title, section, and closing titles) take an optional `size` of `l`, `m`, or `s`, all theme tokens of at least 24px. Left out, the renderer picks the step from the node's text: a character load against a theme budget, scaled by the room the slide's heading leaves (`crowding` on the render context), or the widest value or word against its column. The layout `fill` role centers with auto margins, so overflow runs down, not over the heading. The deck viewer and the studio's slide grid flag a slide whose content leaves its frame body.
- **Studio sessions**: MCP sessions opened against an older evaluation of the studio's server code answer 404, so a client reconnects with current tools instead of validating against a stale schema.
- **Style collection**: `runtime.surfaces.html.createStyleCollection(composition, options?)` (SDK: `createHTMLStyleCollection`) returns `{ context, css() }`, the html surface's CSS collected from a React render the host does with `context`, so a React tree in a shadow root renders once for its styles. The html surface's own collection pass runs through the same helper.
- **Studio deck list**: Each deck shows its first slide and can be deleted. Every slide the viewer and studio draw sits in its own shadow root with only that slide's CSS.
- **Surface `heading`**: `text`, `markdown`, and `slack` take `heading`, as `react` and `html` already did. Slide hosts pass `false` on every surface: each slide opens with its own `#` heading (`slideTitle`, `slideSection`, `slideHeading`, `slideClosing`), sub-headings sit at `##`, and `slideRender` and `slideRenderGrid` set the slide they embed apart on text, Markdown, and Slack. `createIsomerTools` takes `heading` for `isomer_render`, and the slides guide says a composition's `title` names the slide rather than repeating its claim.

- **Creation**: Initial Isomer OKF v0.2 bundle covering the workspace, `@elastic/isomer-sdk`, `@elastic/isomer-runtime`, `@elastic/isomer-primitives-slides`, `@elastic/isomer-image-takumi`, and `@elastic/isomer-evals`.
- **Slides primitives**: Added `slideTable` (the pack's first native `slack` renderer), `slideTranscript`, `slideWindow`, `slideCycle` (inline SVG with literal paint), and `slideCode.highlight`. Containers now dispatch Slack per child through `scope.renderSlack`.
- **Isomer deck**: `docs/deck` is a private Vite app of slide compositions, one `.tsx` file each. The docs workflow builds it and deploys it at `/deck/` beside the docs-builder site.
- **License artifacts**: The generated runtime inventory now includes declared Takumi platform dependencies and fails when their notice or license text is unavailable.
- **MCP and agent tools**: Added `@elastic/isomer-mcp`. `./tools` turns any runtime into five transport-neutral tools (authoring guide, validate, render, list views, request view) and never reaches the MCP SDK; the root entry registers them on an MCP server with the guide as a resource and a `compose` prompt.
